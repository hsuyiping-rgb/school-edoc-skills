# 二代公文核閱（校長）

以國小校長的角色，把主管待辦理區的公文**逐件讀完 → 分流擬意見 → 校長確認 → 送出**。Agent 是幕僚，校長是決行者。

## 護欄（每次都適用）

- **校長本人**處理登入、驗證碼、自然人憑證 PinCode（錯三次鎖卡）。Agent 遇到這些畫面就停下，交給校長。
- **送出前逐件取得明確同意**。「決行」「退承辦人」按下即送出，沒有二次確認。
- **D 類重大案件**只整理案情與選項，由校長裁示。
- 公文內容、個資不寫進任何檔案；紀錄只記件數與處置類型。查名冊時只看本校的列，用 `--grep` 過濾；為判讀掃描檔產生的頁面圖片，用完即刪。
- 用 **Claude in Chrome**（內建瀏覽器會被轉跳頁關掉）。

## 步驟

### 1. 進入系統
**一開始（含每次「開工」後）就主動把公務雲登入頁顯示給校長**，不用等校長開口：
1. `list_connected_browsers` 選標記 `onThisComputer` 的 Chrome（別台電腦的不要選）。
2. `tabs_context_mcp`（createIfEmpty）→ navigate `https://cloud2.ntpc.gov.tw/login`，截圖確認出現帳號、密碼、驗證碼欄位。首頁如果跳出「請重新登入」，直接開 `/login`。
3. 告訴校長：登入頁已開在本機 Chrome 的 Claude 分頁群組；請確認帳號欄沒有被自動填錯，再輸入驗證碼登入，也可以用自然人憑證登入。舊的二代公文分頁若顯示「系統發生錯誤」，那是逾時的舊分頁，不是登入處。

校長說「已登入」後，依 [`references/操作手冊.md`](references/操作手冊.md) 第一節完成 SSO → 開 `OdMainFrame.aspx`。
完成條件：看得到「待辦理區 > 待審核(N)」。

### 2. 盤點待核清單
待簽收區與待辦理區都看。用 [`scripts/list_pending.js`](scripts/list_pending.js) 讀出每件的文號、類別（收／創）、主旨、限辦日期、承辦單位。
完成條件：清單件數與頁面「總筆數」一致。

### 3. 逐件讀文與附件
每件用 [`scripts/open_doc.js`](scripts/open_doc.js) 開啟，`get_page_text` 讀全文：來文或簽稿、承辦擬辦、會辦與簽核流程。

**有附件就開附件**（校長要求，不可省略）。依操作手冊第三節，附件有兩種來源：
- **系統內附件**：左側「來文／稿」分頁有迴紋針圖示，用 [`scripts/download_attachments.js`](scripts/download_attachments.js) 下載。
- **附件下載區**：公文附件欄寫「請至附件下載區…驗證碼：…」，用發文文號＋驗證碼查詢後下載。

下載後用 [`scripts/read_attachments.py`](scripts/read_attachments.py) 讀取；掃描檔沒有文字層，轉成圖片判讀。附件要拿來**核對承辦的說法**：名單上有沒有本校、人數金額是否一致、期限與規定是否被遺漏、本校要做哪些事。
完成條件：**每一件**都讀完本文與全部附件，並能說出「來文要學校做什麼」「承辦擬做什麼」「附件核對結果」。空白表單類附件可以只看檔名，但要在呈報中列出。

### 4. 分流與擬意見
依 [`references/審核準則.md`](references/審核準則.md) 逐件套用檢核表，歸入 A／B／C／D，擬出可直接貼進意見欄的文字。
最常見的缺口是**擬辦與來文要求不對稱**：來文要求行動、推薦人選、報送或播放，承辦只擬「敬悉」「公告周知」「文存參」。這時以 B 類補上具體交辦，或以 D 類請示。
完成條件：每件都有分流、理由與擬填意見；自訂的內部期限要標明是建議值。

#### 採購案件：自動調用審查技能（校長要求，不用等校長開口）
盤點或讀文時，只要該件是**採購簽**（主旨或說明出現採購案號、招標、公開取得、限制性招標、決標、議價、監辦、驗收、變更設計等），讀完本文與附件後就直接調用審查技能，不另外請示：
- **上網公告前的招標簽**（附投標須知、契約、需求說明書、估價單、監辦通知單）→ 調用 `tender-review`。
- **工程案的其他階段**（預算書圖、決標紀錄、變更設計、初驗、驗收、結算）→ 調用 `eng-procurement-review`。
- 做法：把附件從「下載」資料夾複製到 scratchpad 再抽取文字。Word 審查報告存到 `<工作區>/採購案/<對應案名資料夾>/<案號>-招標文件審查報告.docx`；找不到對應資料夾就存在 `<工作區>/採購案/` 下，並告訴校長存放位置。
- 呈報時，在第 5 步的表格中把這件列為 D 類，附上報告重點（重大／應補正件數與主要問題），以及依報告擬好的退回或核定意見。
- 未達公告金額、看起來很例行的採購（例如評選委員圈選簽、小額財物）也要跑；附件不足以審查的，在呈報中註明缺哪些文件。

### 5. 向校長呈報
用一張表呈報（件號、主旨摘要、承辦擬辦、附件核對結果、問題、建議批示）。附件沒能打開的件要標明，不能當作已核對。A／B 類可合併成表，D 類逐件列出選項。結尾請校長用固定用語回覆：
- 「**採用建議**」：填入 Agent 擬的意見
- 「**如擬**」：批「如擬。」，同意承辦的擬辦
- 「**退回**」：填退回意見，按退承辦人
- 或由校長直接給意見文字

完成條件：每一件都收到校長的明確回覆。沒有回覆的件，維持原狀不送出。

### 6. 逐件送出
依操作手冊第四節，每件分兩個 batch：先開文，再「點意見欄＋[`scripts/fill_and_submit.js`](scripts/fill_and_submit.js)」。腳本會檢查文號、焦點與寫入文字，三道都通過才按鈕。
- 出現 PinCode 視窗：停下，請校長輸入。
- 腳本回報 `ABORT`：代表還沒送出，重點意見欄再執行一次。
完成條件：每件都看到「決行作業成功」或「退承辦人作業成功」，最後重讀清單，確認已處理的件都不在清單上。

### 7. 收尾
**清除附件**（校長要求）：全部公文送出、清單確認清空後，用 [`scripts/cleanup_attachments.ps1`](scripts/cleanup_attachments.ps1) 把本次下載的附件移到資源回收筒。`-Since` 填開始下載附件前的時間；先不加 `-Recycle` 列出清單，確認全是本次附件再加 `-Recycle` 執行。只移到回收筒，不做永久刪除。
完成條件：腳本回報的件數與本次下載數一致，「下載」資料夾中已沒有本次附件。

在專案 `handoff.md` 記下日期、件數、處置類型分布，以及需要追蹤的事項（退回件重陳要檢查哪些點、有期限的交辦）。
向校長回報成果表；過程中有異常（例如誤觸編輯區後復原）要如實說明。

## 參考
