# 二代公文核閱（校長）

以國小校長的角色，把主管待辦理區的公文**逐件讀完 → 分流擬意見 → 校長確認 → 送出**。Agent 是幕僚，校長是決行者。

## 護欄（每次都適用）

- **校長本人**處理登入、驗證碼、自然人憑證 PinCode（錯三次鎖卡）。Agent 遇到這些畫面就停下，交給校長。
- **送出前逐件取得明確同意**。「決行」「退承辦人」按下即送出，沒有二次確認。
- **D 類重大案件**只整理案情與選項，由校長裁示。
- 公文內容、個資不寫進任何檔案；紀錄只記件數與處置類型。查名冊時只看本校的列，用 `--grep` 過濾；為判讀掃描檔產生的頁面圖片，用完即刪。
- 用 **Claude in Chrome**（內建瀏覽器會被轉跳頁關掉）。

## 步驟

### 1. 進入系統
**一開始（含每次「開工」後）就主動把公務雲登入頁顯示給校長**，不用等校長開口：
1. **先確認本機真的有在跑 Chrome，再選瀏覽器**。`onThisComputer` 標記可能是舊的：實測曾遇到某個連線標著 `onThisComputer`，本機卻沒有開 Chrome，結果登入頁開到別台電腦。
   - PowerShell 執行 `(Get-Process chrome -ErrorAction SilentlyContinue | Measure-Object).Count`。結果是 0 → 本機沒開 Chrome，清單上任何一個都不是本機。這時先用 `Start-Process chrome.exe -ArgumentList '--profile-directory="<公務帳戶的設定檔>"','https://cloud2.ntpc.gov.tw/login'` 開啟，請校長按擴充圖示連線，再重新查清單。
   - `list_connected_browsers` 選 `onThisComputer` 的那一個；`connectedAt` 要是校長剛連線的時間，不能是很久以前的舊連線。別台電腦的不要選。
2. `tabs_context_mcp`（createIfEmpty）→ navigate `https://cloud2.ntpc.gov.tw/login`。開好後再驗一次是不是本機：PowerShell 執行 `Get-Process chrome | ? MainWindowTitle | % MainWindowTitle`，要看到「新北公務雲」這個視窗標題；看不到就是開到別台電腦，回到第 1 步。截圖確認出現帳號、密碼、驗證碼欄位。首頁如果跳出「請重新登入」，直接開 `/login`。
3. 告訴校長：登入頁已開在本機 Chrome 的 Claude 分頁群組；請確認帳號欄沒有被自動填錯，再輸入驗證碼登入，也可以用自然人憑證登入。舊的二代公文分頁若顯示「系統發生錯誤」，那是逾時的舊分頁，不是登入處。

校長說「已登入」後，依 [`references/操作手冊.md`](references/操作手冊.md) 第一節完成 SSO → 開 `OdMainFrame.aspx`。
完成條件：看得到「待辦理區 > 待審核(N)」。

### 2. 盤點待核清單
待簽收區與待辦理區都看。用 [`scripts/list_pending.js`](scripts/list_pending.js) 讀出每件的文號、類別（收／創）、主旨、限辦日期、承辦單位。
完成條件：清單件數與頁面「總筆數」一致。

### 3. 逐件讀文與附件
每件用 [`scripts/open_doc.js`](scripts/open_doc.js) 開啟，`get_page_text` 讀全文（來文或簽稿、簽核流程），**再跑 [`scripts/read_opinions.js`](scripts/read_opinions.js) 讀承辦／會辦／核判三個頁籤的意見**。`get_page_text` 只讀得到預設的「承辦」頁籤，會辦人的意見（例如「職以公假登記出席」）要切頁籤才看得到；漏讀會把已有擬辦的件誤判成「擬辦未回應」（實測曾發生）。

**有附件就開附件**（校長要求，不可省略）。依操作手冊第三節，附件有兩種來源：
- **系統內附件**：左側「來文／稿」分頁有迴紋針圖示，用 [`scripts/download_attachments.js`](scripts/download_attachments.js) 下載。
- **附件下載區**：公文附件欄寫「請至附件下載區…驗證碼：…」，用發文文號＋驗證碼查詢後下載。

下載後用 [`scripts/read_attachments.py`](scripts/read_attachments.py) 讀取；掃描檔沒有文字層，轉成圖片判讀。附件要拿來**核對承辦的說法**：名單上有沒有本校、人數金額是否一致、期限與規定是否被遺漏、本校要做哪些事。
完成條件：**每一件**都讀完本文與全部附件，並能說出「來文要學校做什麼」「承辦擬做什麼」「附件核對結果」。空白表單類附件可以只看檔名，但要在呈報中列出。

### 4. 分流與擬意見
依 [`references/審核準則.md`](references/審核準則.md) 逐件套用檢核表，歸入 A／B／C／D，擬出可直接貼進意見欄的文字。
最常見的缺口是**擬辦與來文要求不對稱**：來文要求行動、推薦人選、報送或播放，承辦只擬「敬悉」「公告周知」「文存參」。這時以 B 類補上具體交辦，或以 D 類請示。
**稿（函稿）只有兩種處置**：沒問題就批「發。」，不另加意見；需要修正就退承辦人，列點寫明修正處，修正後再陳。不得擬「發。惟請修正……」這種「發＋審查意見」的批示。
完成條件：每件都有分流、理由與擬填意見；自訂的內部期限要標明是建議值。

#### 採購案件：自動調用審查技能（校長要求，不用等校長開口）
盤點或讀文時，只要該件是**採購簽**（主旨或說明出現採購案號、招標、公開取得、限制性招標、決標、議價、監辦、驗收、變更設計等），讀完本文與附件後就直接審查，不另外請示。分兩層：

**第一層：判讀（每件採購簽都做）**，產出依 `eng-procurement-review` 的格式：「可簽／緩簽／退回」＋理由逐條附依據＋已查無問題＋可直接貼進意見欄的批示文字。不產檔案。
- **工程案**（任何階段）→ 用 Skill 工具調用 `eng-procurement-review`，照它的流程跑完整檢核。
- **財物、勞務案的招標簽**（含工程的委託設計監造技術服務）→ 不調用技能，改讀 `~/.claude/skills/tender-review/references/checklist.md` 與 `legal-basis.md` 當檢核清單，問題分四級後，依 `eng-procurement-review` 步驟 6 的規則換算結論：有「重大」就退回，只有「應補正」就緩簽，其餘可簽。
- 附件先從「下載」資料夾複製到 scratchpad 再抽取文字（`tender-review/scripts/extract_docs.py`）。

**第二層：Word 審查報告（只在需要時做）**
- 判讀結論是**退回**，或校長要求書面資料時，才用 Skill 工具調用 `tender-review`，產出 Word 報告。
- 報告存到 `<工作區>/採購案/<對應案名資料夾>/<案號>-招標文件審查報告.docx`；找不到對應資料夾就存在 `<工作區>/採購案/` 下。
- **退件前先把報告上傳成公文附件**（校長要求）：呈報時一併請校長同意「上傳報告附件＋退承辦人」。同意後，第 6 步該件的順序改為：開文 → 工具列「附件」上傳報告（用 Claude in Chrome 的 `file_upload`）→ 確認附件清單出現報告檔名 → 填意見 → 退承辦人。退件意見末句寫「詳細審查意見如附件審查報告」。
  - 退回後公文就離開校長的清單，可抽回區通常也找不到，事後無法補附，所以一定要在按「退承辦人」**之前**上傳。
  - 上傳失敗或找不到上傳入口時，不要送出：先回報校長，改用「退件意見末句寫『詳細審查意見另以書面提供』，由校長轉交承辦處室」。
  - 首次實際操作時截圖記下「附件」視窗的步驟，成功後補進 `references/操作手冊.md` 第四節。

呈報時，在第 5 步的表格中把這件列為 D 類，寫出判讀結論、主要問題與擬填意見。未達公告金額、看起來很例行的採購（例如評選委員圈選簽、小額財物）也要做第一層；附件不足以判讀的，註明缺哪些文件。

### 5. 向校長呈報
用一張表呈報（件號、主旨摘要、**公文摘要**、承辦擬辦、附件核對結果、問題、建議批示）。「公文摘要」用 2–3 句寫出公文實質內容：來文單位要學校做什麼（對象、期限、金額、名額），或簽要做什麼（事由、經費、時程），讓校長不開原文也能掌握；不寫個資。附件沒能打開的件要標明，不能當作已核對。A／B 類可合併成表，D 類逐件列出選項。結尾請校長用固定用語回覆：
- 「**採用建議**」：填入 Agent 擬的意見
- 「**如擬**」：批「如擬。」，同意承辦的擬辦
- 「**退回**」：填退回意見，按退承辦人
- 或由校長直接給意見文字

完成條件：每一件都收到校長的明確回覆。沒有回覆的件，維持原狀不送出。

### 6. 逐件送出
依操作手冊第四節，每件分兩個 batch：先開文並量出決行鈕座標，再「點意見欄 → 等 1 秒 → [`scripts/fill_and_submit.js`](scripts/fill_and_submit.js) 填意見 → `computer left_click` 決行 → 輪詢結果」合併成一步。腳本只填意見，文號、焦點、文字、按鈕位置任一項不符就中止，後面的點擊不會執行。
- 出現 PinCode 視窗：停下，請校長輸入。
- 腳本回報 `ABORT`：代表還沒送出，重點意見欄再執行一次。
- 附審查報告的退件：先完成附件上傳並確認檔名出現，再填意見、退承辦人（見第 4 步「第二層」）。
完成條件：每件都看到「決行作業成功」或「退承辦人作業成功」，最後重讀清單，確認已處理的件都不在清單上。

#### 件數多時：用 subagent 分組送出（校長同意）
逐件串行送出很慢（每件約 30 秒）。第 5 步每一件都取得校長明確回覆後，送出階段可以用 Agent 工具分派 subagent 平行處理：
1. **第一件由主線送出**：校長輸入 PinCode、看到「作業成功」後才分派，避免多個 subagent 同時卡在 PinCode。
2. **分組**：其餘件每組 3–5 件，最多 4 個 subagent。附審查報告要上傳附件的退件，仍由主線處理。
3. **prompt 要自足**，每個 subagent 帶入：
   - 已選定的 Chrome deviceId（`onThisComputer` 的那個）。
   - 該組每件的文號、**意見全文（逐字照貼，不得改寫）**、動作（決行／退承辦人）。
   - 本技能 `scripts/` 的路徑與操作手冊第四節的步驟。
4. **subagent 的做法**：
   - 先 `tabs_create_mcp` 開自己的分頁，不碰主線和其他 subagent 的分頁（同一個 SPEED 分頁不能並行操作）。
   - 在自己的分頁開 OdMainFrame → 待辦理區 → `open_doc.js` → 定位意見欄 → 點擊並等 1 秒 → `fill_and_submit.js` → `computer left_click` 決行 → 輪詢到「作業成功」。一件完成才做下一件。
   - 遇到 PinCode、同一件 `ABORT` 兩次、錯誤訊息、找不到文號、權限審查拒絕：**停止該組並回報**，不重試、不換方法。
   - 結束時關閉自己的分頁，回報每件的文號和結果字串。
5. **主線收尾**：彙整各組回報，重讀清單，確認已處理的件都不在清單上；未完成的件列給校長。

權限審查擋下送出時，不得改用 subagent 規避；停下來請校長確認或親自處理。
（2026-10 加入，尚未實測：首次使用時先派 2 個 subagent，確認 Chrome 擴充能同時驅動多個分頁、SPEED 不會互相踢出登入，再把結果補進操作手冊第四節。）

### 7. 收尾
**清除附件**（校長要求）：全部公文送出、清單確認清空後，用 [`scripts/cleanup_attachments.ps1`](scripts/cleanup_attachments.ps1) 把本次下載的附件移到資源回收筒。`-Since` 填開始下載附件前的時間；先不加 `-Recycle` 列出清單，確認全是本次附件再加 `-Recycle` 執行。只移到回收筒，不做永久刪除。
完成條件：腳本回報的件數與本次下載數一致，「下載」資料夾中已沒有本次附件。

在專案 `handoff.md` 記下日期、件數、處置類型分布，以及需要追蹤的事項（退回件重陳要檢查哪些點、有期限的交辦）。
向校長回報成果表；過程中有異常（例如誤觸編輯區後復原）要如實說明。
