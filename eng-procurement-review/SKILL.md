# 工程採購簽核判讀（新北市立學校）

## 立場

使用者是**簽名的人**，不是備文件的人。

所以這支技能不產「應補正文件清單」——那是承辦拿去催件的東西。它回答的是一個問題：
**這份東西我現在能不能簽？** 不能簽的話，給一段可以直接貼進批示欄的話。

三個由此而來的原則：

1. **結論先出，理由在後。** 使用者要在幾分鐘內決定，不是讀一份報告。
2. **不寫個人責任，寫程序後果。** 不說「校長須負責」，說「該程序瑕疵於驗收階段無法補正」。
   資訊完全一樣，但落在紙上的是法規事實，不是對自己的指控。
3. **退件意見要中性。** 那段話承辦會看到。目的是讓下一次送上來的品質提升，不是究責。

## 主幹是新北市，不是中央

新北市立學校辦工程採購同時受三層拘束，而**《新北市政府所屬各機關辦理採購規範》
（115年6月版）是主幹**——它把中央要求包進去後又加了市府層級，加上去的那些正是最常漏的。

只查中央法規會漏掉：外聘書圖審查委員、外聘專家審監造計畫、工地督導頻率、
250 萬的撥款與工程管理費門檻、報教育局協驗、履約計分填報。這些全部落在
150 萬～1000 萬 這個學校最常見的區間裡。

**檢核以 `references/ntpc-rules.md` 為主**，中央法規（採購法、工程會品質管理作業要點）
只在需要引法源或市府規範未涵蓋時進場。

## 產出

**兩段文字，直接在對話裡講完，不產生檔案。**

### 第一段：判讀

```
【判讀】退回

本案 XXX 萬元，屬公告金額以上未達查核金額之工程採購。

不能簽的原因（2 項）：
1. 招標文件書圖未經第二級審查。學校無工程技術職系人員，
   150 萬以上工程採購依採購規範第五點(一)3但書(1)應準用第二級，
   需中階以上主管召集並邀集至少 2 名外聘審查委員。卷內僅見逐級陳核。
2. 監造計畫未見外聘專家審查意見表。依採購規範第二十三點後段(一)，
   公告金額以上工程之監造計畫審查，機關無工程品質管理經驗之技術職系人員
   參與時應聘請專家學者協助，並依(三)填具審查意見表、(四)逐項確認修正後核定。

程序後果：上述二項屬招標前應完成之審查程序，於決標後無法回溯補正。

已查無問題：預算書已編列品管費與材料設備抽驗費、廠商資格載明營造業登記、
等標期符合、契約採新北市政府工程採購契約範本（115年5月版）。
```

要素固定：**結論 → 定錨數字 → 不能簽的理由（逐條附依據）→ 程序後果 → 已查無問題**。

「已查無問題」那段不能省。它讓判讀可信，也讓使用者知道哪些不必再看。

### 第二段：退件意見稿

中性、可直接貼進批示欄或退文，通常 3～5 行。不寫「承辦疏失」這類字眼。

```
【退件意見稿】

本案請補正後再會核：
一、依《新北市政府所屬各機關辦理採購規範》第五點第一款第三目但書規定，
    本案屬公告金額以上工程採購，請依第二級方式辦理招標文件書圖審查，
    並依同點第二款請審查委員具結（附件一）。
二、監造計畫請依同規範第二十三點規定，聘請專家學者協助審查並填具審查意見表，
    逐項確認修正後陳核。
```

## 工作流程

### 步驟 1：讀出文件

```bash
python scripts/extract_docs.py <案件資料夾> -o <輸出資料夾>
```

處理 `.docx`（含表格）、`.doc`、`.pdf`（Big5 CID 公文也能讀）、`.xlsx/.ods`。

**一定要把預算書（詳細價目表）的表格讀出來**——工程性質判定、有沒有漏編品管費與
勞安費、單價分析在不在，全部靠它。

### 步驟 2：判斷這是哪一關

只做**五關**（使用者實際會簽名的地方）：

| 關 | 看到這些文件 |
|---|---|
| **需求核定** | 需求簽呈、經費核定函、預算書圖、設計圖說 |
| **發包（公告前）** | 投標須知、契約草案、招標公告稿、書圖審查紀錄 |
| **決標** | 開標／比價／議價紀錄、決標紀錄、廠商資格查驗 |
| **變更設計** | 變更原則會勘紀錄、變更設計簽陳、變更前後對照表 |
| **驗收** | 竣工報告、初驗紀錄、驗收紀錄、結算明細表、結算驗收證明書 |

開工、估驗計價、保固通常由主任決行，不上到校長。這三關在
`references/document-inventory.md` 留有簡表——**驗收那一關要回頭查開工文件補齊了沒**，
因為開工漏掉的東西會在驗收爆開。

文件名稱不足以判斷時（承辦常把所有東西塞一個資料夾），**直接問是要送哪一關**，不要猜。

### 步驟 3：鎖定五個定錨事實

寫在判讀最前面。後面每一條檢核都依賴它們：

| 事實 | 去哪裡找 | 連動 |
|---|---|---|
| 採購標的性質（工程／財物／勞務） | 預算書品項、簽呈 | 契約範本、廠商資格、勞安責任、請照 |
| 預算金額 | 簽呈、預算書 | 全部門檻 |
| 是否涉及建築行為（新建／增建／改建／修建） | 預算書、設計圖說 | 要不要請照、要不要建築師或技師 |
| 是否為供公眾使用建築物之室內裝修 | 施工範圍、樓層用途 | 室內裝修審查許可 |
| 監造方式（自辦／委外） | 簽呈、技術服務契約 | 監造計畫審查與人員設置 |

工程性質判定是最容易錯的一步，判準與學校六種典型誤判見 `references/nature-test.md`。
判不出來時不要硬猜，列為「須先釐清事項」——性質未定，整案的程序基礎就是浮動的。

### 步驟 4：跑檢核

1. **先讀 `references/ntpc-rules.md`**，那是主幹。按判定的關別跑對應段落。
2. `references/stage-checklist.md` 是五關的實際檢核點，含跨階段一致性。
3. `references/thresholds.md` 查金額門檻（新北市層在前，中央層在後）。
4. `references/parallel-duties.md` 查採購法以外的併行義務（建築法請照、室內裝修許可、
   職安法 §26 書面告知、消防、石綿、無障礙）。

**門檻是雙向的。** 同時指出「該有而沒有」和「不該有卻要求」——後者會墊高廠商成本、
減少投標家數，一樣是缺失。

### 步驟 5：發包關要讀 tender-review 的參考檔

如果判定在**發包（公告前）**這一關，採購法層的合法性（等標期、綁標、範本殘留、
規格不足）以 `tender-review` 為準。**讀它的參考檔，不要用 Skill 工具呼叫它**：

```bash
~/.claude/skills/tender-review/references/legal-basis.md   # 法條對照、招標期限標準、查證守則
~/.claude/skills/tender-review/references/checklist.md     # 按文件別組織的檢核清單
~/.claude/skills/tender-review/references/spec-patterns.md # 規格不足時的補正範式
```

**為什麼不呼叫：** 用 Skill 工具叫起 `tender-review` 會把它整套工作流程載進來，
包含寫 JSON、跑 `build_report.js` 產 Word、再跑 `render_check.py` 驗排版。
那與本技能「零檔案、兩段文字」的產出相衝突，而且會把判讀拖成一份報告。
讀參考檔可以取得同一套法源與檢核邏輯，產出仍由本技能控制。

**不要自己另寫一套採購法檢核。** 兩支技能共用 `tender-review` 的法源，
本技能只負責文件齊備性與新北市層規定。

其餘四關不需要讀這些檔案。

### 步驟 6：換算成三態（硬規則）

`tender-review` 回來的是四級（重大／應補正／建議／已符合），那是承辦視角。
本技能自己的發現也用同一套四級標記。然後**機械換算**：

| 條件 | 結論 |
|---|---|
| 出現任一「**重大**」 | **退回** |
| 無重大，但有「**應補正**」 | **緩簽**（補齊後再簽） |
| 只有「建議」或全部「已符合」 | **可簽** |

**這個換算不做例外。** 審查工具的價值來自可預測——如果它有時候把「重大」判成可簽，
使用者就必須每次重讀全文，那它就沒省下任何東西。

要偏離結論，由使用者自己偏離。工具不替他做那個動作，也不在判讀裡建議他偏離。

四級的判準：
- **重大** — 違法，或程序瑕疵於後續階段無法補正。
- **應補正** — 文件缺漏或不完備，補齊即可繼續。
- **建議** — 不違法，但影響品質、進度或後續爭議處理。
- **已符合** — 明確查過沒問題。

### 步驟 7：引用法規時保持誠實

**寫錯的條號會被承辦原封不動抄進公文。** 讀 `references/legal-sources.md`。

- 新北市採購規範引「第 X 點第 X 款」，**不要寫成「條」**。
- 採購法本文條號可憑記憶；日數、比率、金額必須查原文。
- **金額門檻標註查證日期。** 現行值與待確認的修法見 `references/pending-changes.md`。
- **CNS 編號一律標示待查**，不確定就用文字描述而不寫編號。
- 新北市**沒有**獨立的小額採購金額函令。要引法源只能引採購規範第十點(二)
  加工程會 111.12.23 工程企字第 1110100798 號函，**不要杜撰新北市自己的函號**。
- `ntpc-rules.md` 是消化版不是原文，判讀中引用具體數字或程序時，
  遇有疑義回原文核對（連結見 `legal-sources.md`）。

### 步驟 8：超出書面審查範圍的，明講

結構安全、消防、電力容量、要不要請照——這些不是讀文件能確認的。
正確寫法不是下判斷，而是：

> 本案施工範圍包含屋頂防水翻修，可能涉及建築法第 9 條所稱「修建」。
> 是否須申請建造執照，建議洽當地建管機關或委請建築師確認，並將確認結果附卷。

判讀末尾固定一句：本判讀僅就所附書面文件為之，未經現場勘查、未查證市場行情，
不代替專業技師或建築師之判斷。

## 需要正式書面報告時

本技能不產 Word。如果案子出事要留書面紀錄、或要送教育局，
改用 `tender-review`——那支有完整的 Word 產製鏈與報告格式。
